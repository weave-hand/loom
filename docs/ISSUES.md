## acl

- [ ] **Catalog reads are auth-only while lineage is per-ref ACL-gated (asymmetry)** `{#iss-catalog-lineage-acl-asymmetry area:acl status:open from:2026-07-09-lineage-table-type-acl-fallback-design pr:- spec:2026-07-12-catalog-dataset-acl-gating-design}`
  `list_datasets`/`get_dataset`/`dataset_preview` take `_subject` **unused** — any authenticated subject can list and preview any dataset — while the `/lineage` reads are per-ref ACL-gated through `LineageVisibility` (seed-gated, cut-not-skip). So a subject can preview a dataset whose lineage node is invisible to them, and vice-viewable metadata discloses more than the governance model intends for the same object. The Table→Type fallback (`2026-07-09-lineage-table-type-acl-fallback-design`) narrowed the practical gap for typed datasets but the structural asymmetry remains. Needs its own design: either per-dataset catalog gating (reusing the same Table→Type resolution) or an explicitly documented coarse-metadata/fine-lineage split. Also related: non-UI callers of `POST /admin/transforms` get no read grant on a physical output table (the UI self-grants to `admin`), leaving such outputs invisible in lineage until granted or bound to a type.

## ontology

- [ ] **`mode=stream` (log) against an existing CDC table is silently accepted** `{#iss-stream-log-vs-cdc-declare area:ontology status:open from:2026-07-07-stream-pk-cdc-tables-design pr:- spec:2026-07-09-stream-log-vs-cdc-declare-design}`
  `reconcile_stream_mode` (`src/control-plane/postgres/src/stream.rs`) rejects a `mode=cdc` request against a table of a different kind, but has NO symmetric guard for the reverse: a `mode=stream&buckets=N` (log) write whose bucket count matches an already-declared **CDC** table falls through the `(Some(n), Some(m))` arm — whose kind-check is gated on `StreamDecl::Cdc` — and is accepted, leaving the registry `kind='cdc'` (rows still hash-bucket, not log-bucket). The asymmetry is essentially forced by slice-2's byte-identical-Log-arm constraint (adding a kind-check to the Log arm would perturb the log/batch path the constraint pins). Reachability is obscure: CDC is declarable only via `POST /models/{type}?mode=cdc`, while `mode=stream` arrives via `POST /datasets/{schema}/{table}`, so both surfaces must target the same physical table. Fix shape: a kind-aware reject in the Log-declare arm that leaves the pure log/batch (no pre-existing CDC row) path untouched, or a single normalized declaration seam both endpoints share. **Also exposed by micro-batch MVs** (`#road-stream-continuous`): a `MicroBatch` output is exempt from the define-time stream-refuse guard (it owns its declared log output via the sanctioned commit path), and its commit declares the output `StreamDecl::Log` — so an MV whose output names a pre-existing CDC table is refused at neither define nor commit and would stamp log-framing into CDC storage. The Log-declare-arm fix here closes that too; the batch-table collision case is already refused at commit. **Plan:** `docs/superpowers/plans/2026-07-09-stream-log-vs-cdc-declare.md` (pre-written at spec time — the implementer starts from it).

## catalog

- [ ] **Operator `POST …/compact` enqueue is non-deduped and unguarded** `{#iss-compact-endpoint-unguarded area:catalog status:open from:2026-07-09-compaction-auto-trigger-design pr:- spec:2026-07-12-compact-endpoint-guard-design}`
  The operator compaction endpoint (`src/services/ingest/http.rs:142-163`) enqueues `compact_table` via plain non-deduped `Queue::enqueue` — repeated POSTs pile up duplicate jobs — and carries none of the eligibility guards the auto-trigger spec derives: it accepts declared stream/CDC tables, changelog tables, and **shadow-flagged** tables, where compaction re-projects files at a higher `begin_snapshot` and COW merge-on-read (highest `begin_snapshot` wins, `iceberg_inline.rs:757-762`) could resurrect tombstoned rows. Surfaced by the `#road-compaction-auto-trigger` spec pass (shipped, PR #419); fix shape: route the endpoint through the same shared guard helper + `pg_insert_if_absent` dedup that trigger introduces (`maybe_enqueue_compact`, `iceberg_compact.rs`). Cross-refs `#road-cow-compaction-consolidation` (shipped, owns the shadow fold).

## query

- [ ] **`/search` over a vector type with a live inline row 500s on the first merge-view query** `{#iss-search-vector-merge-view-nullable area:query status:open from:2026-07-07-search-cold-suppression-design pr:- spec:2026-07-09-search-vector-merge-view-nullable-design}`
  `engine-serving`'s `build_merge_view` (`src/services/engine-serving/src/serving.rs`) UNION-ALLs the file tier (non-null `vector(N)` column) with the inline tier and projects back to the mirror schema, which declares that column **non-nullable**; a tombstone/inline delta puts a NULL under a non-nullable field, so the merged-view/hot-delta read throws `Invalid argument error: Column '<vec>' is declared as non-nullable but contains null values` (500). (Diagnosis corrected while speccing: the failure is **deterministic** arrow `RecordBatch::try_new` validation — not first-query DataFusion nondeterminism — at two sites: `inline_delta_batch`'s hot-delta scan scoring tombstone/`-U` rows, and latently `build_inline_provider`'s non-nullable declaration over tombstone rows; see the spec.) Latent until now: no test combined a live inline row with a `vector(N)` column, and `/search`'s survivor post-filter only reached the merge view for row-filtered types — now, after the `#iss-search-cold-superseded-hits` fix, for every identity-bearing type. Surfaced by that fix's e2e (`vector_search_cold_suppression_e2e.rs`, both cases `#[ignore]`'d pending this). Fix shape: make the merged view's projected `vector(N)` nullability consistent with the union (widen to nullable, or coerce), and eliminate the first-query nondeterminism; then un-ignore the two e2e cases. **Plan:** `docs/superpowers/plans/2026-07-09-search-vector-merge-view-nullable.md` (pre-written at spec time — the implementer starts from it).
- [ ] **410 retention-horizon guard is over-conservative for a quiet table** `{#iss-timetravel-quiet-table-overconservative area:query status:open from:2026-07-06-timetravel-reads-design pr:- spec:-}`
  `ensure_within_retention` (`src/services/query-api/src/handler.rs`) 410s a time-travel read (`?as_of`/`?as_of_snapshot`) whenever the resolved snapshot `at` is older than the GC retention horizon `H`, even when the target table was never rewritten since that snapshot — its rows were never end-capped, so nothing was reclaimable and the read would in fact be complete. Root cause: the guard's originally-intended per-table "quiet-table exemption" is unimplementable via `Catalog::current_snapshot`, which under loom's single catalog-global `iceberg_mirror.snapshot_seq` always returns the global tip (`>= H` for any live table), not the table's own last-write snapshot — so `at < H` already implies `at < current_snapshot(table).id` and the exemption can never independently flip a verdict; it was removed as dead code. A precise exemption needs a distinct per-table last-write catalog query. Workaround: read live (no selector) or pick a snapshot `>= H`.

## transform

- [ ] **`mv_delta_scan` can't read an inline-only table as a delta source until first flushed** `{#iss-mv-delta-inline-source-unflushed area:transform status:open from:2026-07-09-stream-joins-design pr:- spec:2026-07-12-mv-delta-inline-source-design}`
  `mv_delta_scan` / `read_files_as_batches` (`engine-serving`) unconditionally calls `catalog.load_table` (`iceberg_read.rs`), which only succeeds for a table that has been flushed to Iceberg at least once (`ensure_iceberg_table` runs on the Parquet-write path, never on the inline-append path). Every micro-batch MV output is written inline-only via `commit_micro_batch` → `inline_append_mv`, so it has no loadable Iceberg table until the byte-threshold auto-flush fires. Consequence: a downstream MV **chained** onto a fresh upstream MV output cannot read that output as its delta **source** until the upstream flushes — the run errors at `load_table` (surfaced by the slice-5 composability e2e `stream_mv_join_triggers.rs`, worked around there with an explicit `flush_table`). Pre-existing slice-4 plumbing gap (`flush_locked`'s own comment anticipates it); surfaced during PR #420. Fix shape: teach `read_files_as_batches` to serve the inline tier (files ∪ inline) when the table has no loadable Iceberg metadata yet, mirroring `build_serving_provider`'s union — related to `#iss-serving-empty-table-not-found`.
- [ ] **End-cap paths don't consult the MV read-position floor — the GC floor alone cannot prevent an MV hole** `{#iss-end-cap-ignores-mv-floor area:transform status:open from:2026-07-12-mv-watermark-aware-gc-design pr:- spec:-}`
  `#road-mv-watermark-aware-gc` (shipped) put the per-bucket MV read-position floor (`mv_floor`, `control-plane/postgres/src/mv_floor.rs`) on `gc_locked`, but **that tier cannot deliver the guarantee its own spec claimed**, and the register should say so. GC only ever reclaims **end-capped** rows/files (`end_snapshot <= H`), while an MV's delta reads **live** rows at the **current** snapshot (`files_with_stats(t, current)` ∪ `inline_live_batch_full(t, current)`, `engine-serving/src/mv_delta.rs`). An end-capped row is therefore already invisible to the MV *before* GC touches it: `gc_table` can never remove a row an MV could still read, so the floor on `gc_locked` buys **byte-retention defense** (a lagging MV's end-capped bytes are not destroyed while it is behind, and the hold is observable via `GcSummary.held_by_mv_floor`) plus a reusable primitive — **not** hole-freedom. The harm is created at **end-cap time**, by whichever path end-caps offsets an MV has not consumed: those rows leave the current snapshot immediately and no downstream GC-tier guard can bring them back. Today's end-cappers are the catalog drop (deliberate destruction — GC's dropped-incarnation reclaim intentionally *bypasses* the floor so drop-GC converges, warning and naming the stranded MVs) and `iceberg_compact::compact_table`, whose plain coalesce re-projects every row (offset framing preserved) and whose eligibility guard skips declared stream tables — but whose operator endpoint does **not** (`#iss-compact-endpoint-unguarded`), and whose COW/shadow fold does not re-project tombstoned rows. The lossy surfaces are coming: CDC changelog retention, stream small-file consolidation, and any truncation/replay/expire surface. **Fix shape:** every end-cap-issuing path calls `mv_floor` for the table **before** end-capping and refuses (or defers) rows/files at or above the floor, the same conservative file-granular bound (`MvFloor::min_offset`) and per-bucket inline bound GC now uses — ideally behind one shared "may I end-cap this row?" seam so future retention paths inherit it structurally rather than by convention. Related: [[fut-mv-cdc-source]] (a CDC source's changelog is exactly the retention-pressured tier), [[iss-mv-register-below-reclaimed-floor]], `#fut-stream-consumer-offsets` (the subscriber cursor the floor was built to union in).
- [ ] **An MV registered against an already-reclaimed source starts below the surviving offset range** `{#iss-mv-register-below-reclaimed-floor area:transform status:open from:2026-07-12-mv-watermark-aware-gc-design pr:- spec:-}`
  A newly registered micro-batch MV has no `stream.mv_watermark` rows, so its floor for every bucket is **0** and its first delta is defined as "the source from offset 0" — but offsets below the floor that was in force *before* it registered may already be gone (GC-reclaimed, or removed by any end-capping path). Nothing validates that at registration: `define_transform` neither reads the source's surviving offset range nor bootstraps a watermark to it, so the MV's first run silently under-reads a short prefix rather than failing loud. Harmless today only because `gc_table` reclaims end-capped rows an MV could not have read anyway (see [[iss-end-cap-ignores-mv-floor]]) — it becomes a real silent hole the moment a lossy end-cap path lands. **Related race, same fix surface:** `mv_floor` is read on the **pool, outside** the GC transaction (`gc_locked`), and MV registration takes no advisory lock, so a `define_transform` that commits in the window between the floor read and the reclaim lets GC reclaim data the brand-new MV expects to read from 0. **Fix shape:** at registration, resolve the source's surviving `(bucket, min(loom_offset))` range and either reject the registration (source already truncated past 0) or **bootstrap** the watermark rows to it (an explicit, recorded "this MV starts here"), and take the same table lock GC serializes under so the floor read and the reclaim cannot straddle a registration.
- [ ] **Pre-declaration data files are held forever by the MV floor's fail-safe** `{#iss-mv-floor-holds-pre-declaration-files area:transform status:open from:2026-07-12-mv-watermark-aware-gc-design pr:- spec:-}`
  `declare_stream` (`control-plane/postgres/src/stream.rs`) can be applied to a table that **already has data files** written as a plain batch table; those files carry no `loom_offset` column stat. The MV floor guard is deliberately fail-safe — a file whose `loom_offset` max stat is missing is **held**, never reclaimed — so once any MV registers against such a table, its pre-declaration files become permanently unreclaimable and inflate `GcSummary.held_by_mv_floor` with no laggard MV to blame (the warning names a bucket's slowest MV; these files belong to no bucket). Bounded, visible, and never lossy — but a genuine "GC never converges for this table" case, and a misleading metric. **Fix shape:** distinguish "no `loom_offset` stat because the file predates the stream declaration" from "no stat because stats are missing" — e.g. record the declaring snapshot on `stream.stream_table` and exempt files whose `begin_snapshot` is below it (they were never part of the offset-framed stream, so no MV can want them), or backfill/deny declaration over a table with existing unframed files. Surfaced by `#road-mv-watermark-aware-gc`.
- [ ] **An in-flight micro-batch run can re-create watermark rows for a def that no longer exists** `{#iss-mv-watermark-ghost-rows area:transform status:open from:2026-07-12-mv-watermark-aware-gc-design pr:- spec:-}`
  The registration→watermark reconciliation is complete on the **admin** paths: `delete_transform` deletes the MV's `stream.mv_watermark` rows with the def, and `define_transform` deletes the *previous* output's rows when a redefinition moves an MV off it (both certified by a testkit contract on both backends), so no watermark key can outlive every def that names it — a ghost key would sit in `mv_floor`'s reader set and floor its source forever, unreachable by any escape hatch. What remains is the inherently **racy** case: a micro-batch run already in flight whose watermark CAS (`advance_mv_watermark`) commits *after* its def was deleted (or redefined away) re-inserts rows under the now-defless `mv` key, since the CAS neither takes the define lock nor re-checks the registration. The source is then floored at that key's offsets with no def to point the operator at, and the only cure is a manual `delete from stream.mv_watermark`. Bounded in practice (one micro-batch's worth of lag, and the MV is being torn down anyway) but it is the same "GC never converges" shape as [[iss-mv-floor-holds-pre-declaration-files]]. **Fix shape:** make the CAS conditional on the def still naming the key (a `where exists (…)` guard, or take the same advisory lock `define_transform` holds), or sweep watermark keys named by no def as part of GC — either way the reconciliation becomes structural rather than best-effort.

## ui

- [ ] **Transforms drawer Run/Delete swallow non-401 errors; Runs tab won't refetch from itself** `{#iss-ui-transforms-drawer-errors area:ui status:open from:2026-07-07-transforms-admin-surface-design pr:- spec:2026-07-09-ui-transforms-drawer-errors-design}`
  The Transforms surface's drawer action paths lack an error surface: `TransformDrawer` has no error slot, so a 400/404/network failure on **Run saved** or **Delete** is silent (a failed delete looks like a no-op). A `401` still fails closed to logout, and the editor-form Define / Run-ad-hoc paths correctly surface `Rejected(body)` via the form's server-error line — only the drawer actions are affected. Fix: add an `action_error: Option<AttrValue>` prop to `TransformDrawer`, render it beside the action buttons, and set it (reusing the surface's `server_error` state) in the `on_run`/`on_delete` `Err(_)` arms. Related edge: the runs-history effect is keyed on `(selection, active_tab)`, so a **Run** fired while the Runs tab is already active clears `tf_runs` but does not re-fire the fetch (the normal flow — Run from the Definition tab flips the tab and refetches — works); fold a runs-generation bump into the Run success path. Both are low-frequency admin-only paths surfaced by this spec's whole-branch review. Sibling of `#iss-ui-swallowed-fetch-errors`. **Plan:** `docs/superpowers/plans/2026-07-09-ui-transforms-drawer-errors.md` (pre-written at spec time — the implementer starts from it).
