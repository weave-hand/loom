## query

- [x] **Puffin-backed vector index (flat/exact, engine-side)** `{#road-puffin-vector-index area:query status:done from:2026-06-27-puffin-vector-index-design pr:#207 spec:2026-06-27-puffin-vector-index-design}`
  Slice 1 of a vector-search capability grounded in arxiv 2606.04196 (Puffin-Backed Vector Indexes for Iceberg), adapted to loom's Postgres-mirror + DataFusion split. A swappable `VectorIndex` trait with a **flat (exact)** first impl: precompute an index over a `vector(N)` column ([[road-vector-column-type]]), store it as an Apache **Puffin** sidecar blob (`loom-vector-index-v1`) in the object store, and bind it to a snapshot via a `vector_index` **mirror** row (loom has no REST catalog, so the mirror replaces the paper's `statistics-file` summary-property binding). Build is a primitive + a `build_vector_index` queue job (worker); the engine-side kNN query merges the **cold** Puffin index with the **hot** un-flushed inline rows (`PgTableProvider` MVCC scan) for exact top-k fresh to the query snapshot. **Deliberately extends** loom's prior "stores, not searches" boundary. Engine-side only (no external endpoint this slice). Approximate ANN (HNSW/Vamana), distributed build, clustering, and staleness-on-flush are deferred to [[fut-puffin-vector-index-ann]].
- [x] **IVF-Flat approximate vector index (engine-side)** `{#road-ivf-vector-index area:query status:done from:2026-06-28-ivf-vector-index-design pr:#210 spec:2026-06-28-ivf-vector-index-design}`
  Slice 2 of the Puffin vector index. A hand-rolled **IVF-Flat** approximate index as a second `VectorIndex` impl behind the trait (deterministic k-means centroids + `nprobe` cluster probing), serialized into the `loom-vector-index-v1` Puffin blob with a `kind=1` payload discriminator and decoded polymorphically (`decode → Box<dyn VectorIndex>`). Selectable at build time via `IndexSpec` (threaded through `BuildVectorIndexJob` + the build gRPC), `Flat` stays the default. **Cold-only approximation:** the inline hot delta is still scored exactly and merged, so freshly-landed rows are never dropped by cluster pruning (`nprobe=nlist` ⇒ exact, the test oracle). Engine-side only. Remaining ANN slices stay in [[fut-puffin-vector-index-ann]].
- [x] **HNSW graph vector index (engine-side)** `{#road-hnsw-vector-index area:query status:done from:2026-06-28-hnsw-vector-index-design pr:#215 spec:2026-06-28-hnsw-vector-index-design}`
  Slice 3 of the Puffin vector index. A hand-rolled **HNSW** (Hierarchical Navigable Small World) graph index as a third `VectorIndex` impl behind the trait, serialized into the `loom-vector-index-v1` Puffin blob with a `kind=2` payload discriminator and decoded polymorphically (`decode → Box<dyn VectorIndex>`). Deterministic build (fixed-seed `SplitMix64` level draws + single-threaded insertion + the diversity neighbor heuristic) keeps the blob byte-identical for a given row order. Build knobs `M`/`efConstruction` ride `IndexSpec::Hnsw` (threaded through `BuildVectorIndexJob` + the build gRPC, defaults `M=16`/`efConstruction=200`); the query knob `efSearch` is a `with_ef_search` setter not yet wired to an external caller (mirrors `nprobe`). `Flat` stays the default. **Cold-only approximation:** the inline hot delta is still scored exactly and merged, so freshly-landed rows are never dropped by graph pruning. Unlike IVF, HNSW has no exact oracle — the cold-side test is a recall threshold. Engine-side only (no external `/search`); Vamana/DiskANN and the remaining ANN slices stay in [[fut-puffin-vector-index-ann]].
- [x] **External `/search` vector kNN endpoint** `{#road-vector-search-endpoint area:query status:done from:2026-06-29-vector-search-endpoint-design pr:#227 spec:2026-06-29-vector-search-endpoint-design}`

- [x] **Vector index auto-rebuild on flush (freshness-on-staleness)** `{#road-vector-index-auto-rebuild area:query status:done from:2026-06-29-vector-index-auto-rebuild-design pr:#240 spec:2026-06-29-vector-index-auto-rebuild-design}`
  A flush end-caps live inline vector rows into a cold Parquet snapshot the Puffin index does not cover; until the next build those rows fall out of *both* k-NN legs (excluded from the live-inline hot delta by `end_snapshot`, absent from the cold index at the older `covered_snapshot`), so just-flushed vectors silently vanish from `/search` results. No threshold (the gap is correctness, not cost); bounded-staleness restore via the queued build, same tradeoff as [[iss-iceberg-inline-visibility]]. Carved slice of [[fut-puffin-vector-index-ann]]; builds on [[road-ontology-vector-index-def]] / [[road-vector-search-endpoint]].
