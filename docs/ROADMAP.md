- [ ] **Iceberg additive schema evolution (add-column + detect/reject)** `{#road-iceberg-schema-evolution area:iceberg status:planned from:iceberg-roadmap pr:- spec:2026-06-23-iceberg-schema-evolution-design}`
  Turn today's **silent** mirror schema divergence into correct additive evolution. A second land's schema is currently projected once at table-create (`columns_exist` guard), so an added column changes the Iceberg metadata but is silently dropped from `iceberg_mirror.column` — reads then return a stale schema. Replace the once-guard with a **reconciliation** step: load the live mirror columns at the parent snapshot and classify the incoming write — *identical* → no-op; *purely additive* (new **nullable** columns appended at end) → project only the new columns with `begin_snapshot = <new snapshot>` (MVCC union); *anything else* (drop/rename/retype/reorder/non-nullable add) → typed `SchemaEvolutionUnsupported` error that aborts the whole commit. Populate the reserved `iceberg_mirror.snapshot.schema_version` with a per-table schema generation (no migration — the column exists). Read side: make the DataFusion serving path (`IcebergMirrorTableProvider`) **mirror-authoritative** (not Parquet-footer inference) and null-fill the new column for pre-evolution files, so current-snapshot reads return the superset schema. Inline path gets detect+reject parity. Promoted from [[fut-iceberg-schema-evolution]]. Out: `field_id` persistence + rename/drop/type-promote, time-travel as-of-schema reconstruction (`iceberg_read.rs` `current_schema()`), additive-inline, DuckLake evolution ([[fut-schema-evolution-coverage]]).
