- [ ] **Per-node ACL filtering of lineage reads** `{#fut-lineage-acl-filtering area:lineage status:deferred from:2026-06-30-lineage-http-read-design pr:- spec:-}`

Needs a `Catalog::exists(&TableRef)` read seam — the catalog is DuckDB-owned and external to loom's Postgres, so it is not cheaply checkable today and the type-only slice deliberately left `Table` targets unvalidated.
- [x] **Queue-driven compaction job + incremental output** `{#fut-compaction-job area:catalog status:promoted from:2026-06-17-compaction-design pr:- spec:-}`
  Promoted to committed work — see [[road-compaction-job]]. Operator-triggered, engine-wire compaction (zero-pool worker streams files over Arrow Flight, commits `compact_files` over a new `EngineControl::CompactTable` RPC). Watermark-tracked **incremental (append-delta)** output remains a deferred follow-on (slice 1 is full-rewrite of the small-file set). Compacted files get fresh row-ids — revisit if row-level deletes land.
- [ ] **Incremental (append-delta) compaction output** `{#fut-compaction-incremental area:catalog status:deferred from:2026-06-22-engine-wire-compaction-flight-design pr:- spec:-}`
  The remaining half of [[fut-compaction-job]]. [[road-compaction-job]] shipped full-rewrite of the small-file set (every small file re-read and coalesced each run). Watermark-tracked incremental output would compact only files added since the last compaction watermark, avoiding O(table) rework on each run. Needs a per-table compaction watermark in the catalog and append-delta selection in the worker. Compacted files get fresh row-ids — revisit if/when row-level deletes land.
- [ ] **Automatic compaction triggering** `{#fut-compaction-auto-trigger area:catalog status:deferred from:2026-06-22-engine-wire-compaction-flight-design pr:- spec:-}`
  [[road-compaction-job]] is operator-triggered only (an explicit `POST …/compact` enqueue), which sidesteps the "when to compact" policy question. Automatic threshold-based triggering — enqueue a `compact_table` job when a table accrues more than N sub-threshold files (mirroring the inline-flush trigger) — is deferred until the policy and back-pressure story is worked out.

- [x] **Define-time chain/link validation** `{#fut-define-time-chain-validation area:ontology status:dropped from:2026-06-15-query-multi-hop-traversal-design pr:- spec:-}`

Once every link is column-validated and endpoint-typed at define time, any chain of *defined* links is structurally sound by construction; ad-hoc multi-hop chains are caller-supplied query paths with no stored artifact to validate at authoring time, so their read-time `BadChain`/`UnknownLink` 400 is the correct surface and remains. - [x] **Update/delete actions** `{#fut-update-delete-actions area:ontology status:promoted from:2026-06-15-actions-part1-design pr:#208 spec:2026-06-27-update-delete-actions-design}`
  Promoted to committed work — see [[road-update-delete-actions]]. `ActionKind` discriminator on `ActionDef`; whole-table copy-on-write via `overwrite_parquet_snapshot` (extended to end-cap the inline tier); identity-targeted PATCH update / single-object delete; coarse `Action::Write` + fine-grained column/row-filter governance on the affected row; vector-bearing types rejected. See deferred follow-ons: [[fut-cow-session-checkin]], [[fut-cow-inline-shadow]], [[fut-cow-file-granular]], [[fut-cow-cas-guard]], [[fut-cow-arrow-native]], [[fut-cow-identity-change]].
- [ ] **Per-session atomic check-in (A6)** `{#fut-cow-session-checkin area:ontology status:deferred from:2026-06-27-update-delete-actions-design pr:- spec:-}`
  [[road-update-delete-actions]] performs whole-table copy-on-write for every update/delete. A per-session check-in model (client locks a logical "session" on an object, mutates it, then commits the changed row without a full-table overwrite) would reduce write amplification for workloads that update individual objects frequently. Deferred until a concrete session-oriented consumer surfaces.
- [ ] **Inline-shadow + merge-on-read + compaction-consolidation (scalable COW)** `{#fut-cow-inline-shadow area:ontology status:deferred from:2026-06-27-update-delete-actions-design pr:- spec:-}`
  The PR #208 scalable design: instead of a full-table Parquet overwrite, land the mutated row into an inline shadow table and let a merge-on-read query union the shadow with the base Parquet (latest shadow wins per identity); a background compaction job consolidates the shadow into a new base snapshot. Avoids O(table) write amplification for hot-update workloads. **Slice 1 carved → [[road-cow-inline-shadow]]** (the `loom_tombstone` model + identity-aware merge-on-read + O(change) mutation write + the per-identity CAS guard, folding in [[fut-cow-cas-guard]]). Remaining slices stay here: **slice 2** = tombstone-aware **compaction consolidation** (fold inline deltas into a new base, clear them, re-enable the suppressed flush — resolves the unbounded-inline-growth slice-1 leaves); **slice 3** = identity-change / upsert ([[fut-cow-identity-change]]). Applies only to identity-bearing types (the merge key); identity-less types keep whole-table COW.
- [ ] **File-granular copy-on-write** `{#fut-cow-file-granular area:ontology status:deferred from:2026-06-27-update-delete-actions-design pr:- spec:-}`
  [[road-update-delete-actions]] rewrites the entire table on every mutation. A file-granular COW (identify the Parquet file(s) containing the target row, rewrite only those files, fast-append the survivors + updated file(s)) would reduce write amplification to O(affected files) rather than O(table). Requires per-file row-id or min/max-based file pruning to locate the target file without a full scan.
- [x] **COW read→commit concurrency CAS guard** `{#fut-cow-cas-guard area:ontology status:promoted from:2026-06-27-update-delete-actions-design pr:- spec:2026-06-30-scalable-cow-inline-shadow-design}`
  Consumed by [[road-cow-inline-shadow]] (slice 1). The original framing — a whole-table snapshot CAS on the read→modify→overwrite window — is superseded by the inline-shadow design's **per-identity** CAS: the O(change) mutation commits its inline delta only if no newer version for that identity appeared since the read, aborting+retrying on conflict (bounded, mirroring compaction). Strictly stronger and cheaper than a whole-table snapshot CAS, and it lands together with the write path it guards rather than hardening the whole-table path after the fact.
- [ ] **Arrow-native COW read leg (lifts the vector guard)** `{#fut-cow-arrow-native area:ontology status:deferred from:2026-06-27-update-delete-actions-design pr:- spec:-}`
  [[road-update-delete-actions]] rejects update/delete on vector-bearing types (`ensure_cow_supported`, `query-api/src/action.rs:427`) because the current COW read leg deserializes rows through `SqlValue` (which has no vector variant). Replacing that leg with a native Arrow batch read (read files as `RecordBatch`, apply the mutation per-batch, write back) would lift the guard and allow update/delete on any type including `vector(N)`. Depends on the file-read infrastructure from [[road-engine-wire-flight]]. **Acceptance criterion (folds in [[iss-overwrite-vector-index-staleness]]):** because lifting the guard first makes UPDATE/DELETE on a vector-**indexed** type reachable, this work must also enqueue a `build_vector_index` rebuild for every declared index on the overwrite/replace commit — populate the `CommitExtras.jobs` seam from a `rebuild_jobs_for(table)` helper shared with `iceberg_flush::flush_table` (which already enqueues rebuilds, see [[road-vector-index-auto-rebuild]]), so the just-rewritten cold rows do not silently vanish from k-NN / `/search` until a manual rebuild.
- [ ] **Identity-change / upsert** `{#fut-cow-identity-change area:ontology status:deferred from:2026-06-27-update-delete-actions-design pr:- spec:-}`
  [[road-update-delete-actions]] forbids changing the identity column (a PATCH that modifies the declared identity field is rejected). Allowing identity mutation (old identity → new identity, essentially a delete + insert) and adding an upsert action kind (insert if absent, update if present by identity) are follow-on governance questions deferred until a consumer needs them.

- [x] **Model constraints** `{#fut-model-constraints area:ontology status:promoted from:to-be-planned pr:- spec:2026-06-30-model-constraints-design}`
  Promoted to [[road-model-constraints]]. - [ ] **Uniqueness constraint (cross-row)** `{#fut-model-constraint-uniqueness area:ontology status:deferred from:2026-06-30-model-constraints-design pr:- spec:-}`
  [[road-model-constraints]] enforces only **per-row** value rules. A non-identity **uniqueness** constraint (a column unique across all rows) needs a cross-row existence check at write — race-prone and index-backed, a different mechanism from per-row validation (closer to `identity`'s primary-key handling). Deferred until a non-PK uniqueness need surfaces; likely rides on the same indexing work that backs identity.
- [ ] **Retroactive constraint validation / backfill** `{#fut-model-constraint-backfill area:ontology status:deferred from:2026-06-30-model-constraints-design pr:- spec:-}`
  [[road-model-constraints]] is **forward-only**: adding or tightening a constraint validates *future* writes but does not re-check existing rows, so already-stored data can violate a newly-declared rule. A backfill/validation pass (scan existing rows against a new constraint, report or quarantine violators, gate the constraint's activation) is deferred until constraint evolution on populated types is needed. Relates to [[fut-ontology-migrations]].
- [ ] **DuckLake vector storage** `{#fut-vector-ducklake area:ontology status:deferred from:2026-06-23-vector-column-type-design pr:- spec:-}`

DuckLake/DuckDB storage of the same logical type (as `FLOAT[N]`, the DuckDB fixed-size array) is deferred — the Grimoire consumer is Iceberg-only, and the Iceberg-default direction makes a DuckLake vector path low-priority. `ducklake_physical_type` returns unsupported for `BaseType::Vector` until this lands.
- [ ] **Semantic description fields across the ontology** `{#fut-ontology-semantic-descriptions area:ontology status:deferred from:to-be-planned pr:- spec:-}`
  Optional human-readable description/documentation strings on ontology entities — object types, properties, and **links** — carried through the ontology store (a nullable column on each `define_*` row) and surfaced on reads. Foundry-style semantic metadata: nothing in the engine consumes it, so it is pure annotation today, but it is the substrate for [[fut-autogen-api-specs]] (richer generated API docs), a future ontology-browsing UI, and LLM/semantic search over the schema. A link carries its own description (the relationship's meaning), distinct from its endpoint types'. Deferred until a consumer needs it: it touches the `core` type/property/link domain structs, the postgres ontology schema (new nullable columns + a migration), and the JSON read serialization, all for metadata no current read path uses.
