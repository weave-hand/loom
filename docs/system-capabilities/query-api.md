# Query API capabilities

The query-api service (`src/services/query-api/`) is loom's governed HTTP surface for reading and mutating typed objects: it resolves the ontology, compiles ACL policy into the SQL it generates (every caller value a bound parameter, never interpolated), and executes on the engine service — the sole serving path, running DataFusion against the Iceberg mirror — as a zero-DataFusion wire client over internal Flight SQL (`CommandStatementQuery`). It covers governed object reads with typed JSON rendering, relational link/multi-hop traversal, recursive `/graph` queries, a typed filter language, object sets and cursor pagination, governed write-back actions (insert/update/delete), and vector kNN search — all behind one deny-by-default governance spine.

_As of 5c5f3092._

## Governed object reads and typed JSON

`GET /objects/{type}` is the primary read: the handler resolves the ontology type to its physical table, gates the subject on `Read` (deny-by-default, and *before* existence is revealed — a denied subject gets 403 whether or not the type exists), folds the subject's policy into a row filter plus denied/masked column sets, compiles a `SELECT` over the allowed projection with the row filters ANDed in, and executes it on the engine. Masked columns render as a `'***'` marker; denied columns are absent. Identifiers come only from trusted ontology/ACL metadata (quoted via `quote_ident`, which escapes embedded quotes rather than panicking (#110)); request-supplied values always bind as parameters — the injection boundary every later slice preserved. The original slice proved this chokepoint chain end-to-end on an embedded DuckDB behind a swappable `ServingEngine` seam; the seam has since been repointed at the DataFusion engine over Flight SQL, and DuckDB is gone entirely — including the multi-file `LIMIT` corruption workaround that engine required (fixed with an `ORDER BY` barrier in #131, then deleted with the engine itself; the upstream-fix follow-up was dropped as moot (#205)).

Results are **typed objects**, not positional rows: the wire shape is `{"objects":[{prop: value, …}]}`, each value rendered by its property's declared logical type via the `core` `JsonRepr` classification. `Long` (int64) deliberately renders as a JSON string (values past 2^53 would silently round as JSON numbers — IDs routinely exceed that), `Integer`/`Double` as numbers, `Date`/`Timestamp` as ISO-8601 strings, and NULL as `null` regardless of type. An unknown logical type or a declared-type/value mismatch falls back to the cell's natural rendering — a permitted read never 500s on a rendering edge case.

Governed reads also feed a second wire: the Arrow Flight **export** listener streams a governed typed-object slice out columnar (the ticket carries a loom `ExportCommand`, not SQL — the ACL'd SQL is compiled server-side per `do_get`, so a forged ticket is still a governed request).

## Derived properties

An `ObjectType` can declare derived properties that aggregate over one of its links — `Customer.orderCount = COUNT` of linked Orders, `totalSpend = SUM(amount)` — computed at read time as correlated subqueries appended to the object read's SELECT (FK and join-table link shapes both supported; COUNT/SUM coalesce to 0 on the empty set, AVG/MIN/MAX go null). Governance is both-ends: the subject must hold `Read` on the linked type and the linked type's row filters apply *inside* the subquery; if the linked type or the aggregated column is unreadable, the derived property is silently **omitted** (treated like a denied column), never an error. Derived properties are projected only — they are not filterable or sortable, and they are served on the plain object read, not on traversal output.

## Link traversal and multi-hop chains

Links are physically resolvable: `LinkDef` carries a `LinkBacking` — a direct foreign-key equijoin or a many-to-many join table — and `GET /objects/{from}/links/{link}` returns the linked target objects as one governed join. Governance composes across both ends: `Read` is required on source and target, the source row filter is ANDed into the join (closing the inference leak where a subject probes hidden source rows through a link), the target row filter and column projection shape the result, and source filter columns must be visible to the caller.

Multi-hop generalizes this to an ordered chain: `GET /objects/{from}/links?_path=l1,l2,…` (depth-capped at 4) compiles a single chain of INNER JOINs, with **every** hop type Read-gated (any denial → 403) and every hop's row filters ANDed in — the N-ends guarantee that a caller reaches final targets only through intermediate rows the policy permits. Only the final target is projected; the single-hop route is the `N=1` case of the same compiler. Caller filters address any position in the chain by link-name prefix (`?placed.status=open` filters the type reached via `placed`; bare keys filter the source), each coerced against *its own* type's declared property types and visibility-checked against *its own* projection. A per-hop filter naming a link that repeats in the path is rejected with a 400 pointing at `/graph` — the deliberate relational/graph boundary.

Every link is also traversable **backwards**, with no declared inverse link: inbound adjacency (`Ontology::links_to`) plus a pure column-role swap (`LinkBacking::reversed()`) let `?_direction=inverse` (single hop) and a `~` path-element prefix (chains) follow a link from its `to` side, governed identically at every hop. An inbound link name matching more than one link is an `AmbiguousLink` 400 — a governed read never silently picks.

## Object identity, association, and identity-keyed dedup

`ObjectType.identity` declares a single primary-key property (validated at bind: it must name a declared, required property). Identity unlocks three read capabilities. First, **association**: `?_shape=association` on the traversal routes returns the edge list itself — deduped `{from, to}` identity pairs typed by each end's logical type — instead of the flattened target set; both projected ends must have a declared, caller-visible identity (you cannot associate objects you cannot identify; intermediates need none). Second, **object sets** (`?_ids=`, below). Third, **correct dedup under masking** (#293): many-to-many traversal originally deduped with `SELECT DISTINCT` over the visible projection, which collapsed *distinct* objects into one row when ACL masked or denied the identity column. Dedup now keys on the raw identity **below the masking layer** — a windowed `ROW_NUMBER() OVER (PARTITION BY t_k.<identity>)` subquery whose outer select keeps the masked/visible projection, so the raw value never leaks but the object count is right; `identity: None` types keep the old `DISTINCT` fallback, and the single-table graph reachability compilers simply dropped their redundant `DISTINCT`.

## Graph queries

`/graph` serves what the relational chain structurally refuses — cyclic, self-link, variable-length paths — as depth-bounded `WITH RECURSIVE` CTEs (depth 1–10, default 5), governed inside the recursion and deduped by declared identity (which need only be *declared*, not visible: it is an internal CTE key). Four axes ship:

- **Bounded reachability** — `GET /objects/{type}/graph/{link}?depth=N`: the deduped set reachable via 1..N hops of a self-link, with the type's row filters applied at the seed, every recursive expansion, and the projection — a blocked intermediate cuts off everything beyond it.
- **Repeated path-cycle** — `GET /objects/{type}/graph?path=l1,…,lK`: a multi-link path that must return to the queried type, repeated up to N times; every intermediate type is Read-gated and row-filtered inside the recursive join. The single-link route is the 1-element case; a non-closing path is a `NotCyclicPath` 400. Since #287, path elements accept the `~` inverse sigil, so `memberOf,~memberOf` answers shared-membership with only one link declared — direction is resolved before compilation (via `links_to` + `reversed()`), so the recursive SQL and its cycle-safety are unchanged.
- **Multi-edge union** — `?links=l1,…,lN`: each recursive step follows *any one* of a set of self-links (FK and join-table freely mixed), compiled as a `UNION ALL` edge relation inside a single recursive step (a DuckDB/DataFusion recursive-CTE constraint allows only one self-reference). `?path=` and `?links=` are mutually exclusive.
- **Recursive core + relational tail** — `?path=knows*,worksAt`: a `*`-suffixed self-link core (the recursion) glued by reachable-set membership to a fixed forward chain landing on a possibly different projected type — "the companies of everyone reachable through `knows`" — in one SQL statement, with the core governed in the CTE and each tail type governed at its alias.

The set routes answer membership only; `?tree=true` on the self-link and path-cycle routes returns the **shortest-path tree** instead (#288): per reachable node, its BFS depth and a parent pointer, settled deterministically (min depth, then min parent identity — scan-order independent), roots included, as a distinct `{roots, nodes}` shape. The per-node depth also delivered the min-depth annotation for the tree shape (#288). Because the tree *projects* identity as `id`/`parent`, it requires a visible identity (masked/denied → 403) — stronger than the set reads.

## Filter language

Every read shares one typed, governed predicate grammar. A query-param key names a column (or `<link>.col` for a chain position); the value carries the operator as `op:operand` — bare value = `eq`; `ne`/`lt`/`le`/`gt`/`ge`; set ops `in:`/`nin:` (comma-separated, with `\,`/`\\` escaping so a literal comma or backslash in a string operand is representable (#145)); bare-token null ops `isnull`/`isnotnull`; and, from #285, `between:lo,hi` sugar and case-insensitive text-pattern ops `contains`/`startswith`/`endswith` (string-only, rendered as `ILIKE` over a bound operand with LIKE metacharacters escaped — a literal `%` matches the character; raw caller wildcards are deliberately not offered). An `eq:` prefix escapes a literal value that would otherwise parse as an operator.

The discipline is **visibility-then-coerce**: a filter column must be in the caller's allowed, unmasked projection *before* the value is parsed (so no operator can probe an invisible column), then each operand coerces to the column's declared logical type — a `Double` filter binds a real double, a `Date` an actual date, never a text comparison. Repeated keys AND together (a `ge:`+`le:` pair is a range). Cross-column disjunction arrived in #289: a reserved `_or` param carries ≥2 member predicates (`col:op:rest`, comma-separated), rendered as one parenthesized OR-group inside the existing AND spine; members reuse the full operator grammar and per-member visibility checks, and governance conjuncts — row filters, `_ids`, ACL — stay strictly ANDed above any OR-group, so disjunction can never weaken a security predicate. `_or` is wired on the object-read endpoint only. Caller predicates always narrow within already-permitted visibility; they never widen access.

## Object sets and reserved control params

`?_ids=1,2,3` scopes any read — plain object read, single-hop, chain, association, and the graph seeds — to a caller-supplied object set addressed by the type's declared identity, lowering to an ordinary `In` predicate on the identity column (so it inherits filter governance verbatim; no identity → 400). All control params live in a reserved `_`-prefixed namespace (`_ids`, `_or`, `_path`, `_direction`, `_shape`), and bind rejects any property or derived-property name starting with `_`, making a control-param/column collision impossible by construction.

## Cursor pagination and type listing

`GET /objects/{type}?limit=&cursor=` pages the object read with a forward-only keyset: `ORDER BY <identity> ASC`, a `> cursor` keyset predicate, fetch `limit+1`, return `{objects, next}` (`limit` clamped to [1, 200]; `next` null on the last page). The path is fail-closed by construction — five 400s fire *before* any SQL or cursor is emitted: no declared identity, a masked/denied identity (a cursor over an unreadable column would leak it), a non-round-trippable identity type (only `Integer`/`Long`/`String`), `_ids` combined with pagination, and a malformed cursor. The default un-paginated read is byte-identical to before (no `ORDER BY`). Alongside it, `GET /ontology/types` lists object-type names via a `gov_list_types` engine-wire RPC — auth-required but not per-type ACL-gated, since the type catalog is ontology metadata (the object *data* stays governed behind `/objects/{type}`). `GET /ontology/types/{name}` (#346) serves one type's full shape — table binding, identity, properties with required flags, and outbound + inbound links — over the same wire-capable reads (`gov_get_type`/`gov_links`/`gov_links_to`), 404 on an unknown type; it is the UI Schema-tab read. Dataset metadata is browsable the same way: `GET /datasets` lists the live mirror tables and `GET /datasets/{schema}/{table}` returns the current snapshot id/time plus the column schema at exactly that snapshot (a self-consistent pair), served through `WireControlPlane::catalog()`'s direct-plane delegation — the queue/lineage precedent — so no catalog RPCs were added (#346).

## Time-travel reads (as-of)

Both `GET /objects/{type}` and `GET /datasets/{schema}/{table}` accept two mutually-exclusive time-travel selectors: `?as_of_snapshot=<i64>` names an exact mirror snapshot id, and `?as_of=<rfc3339>` resolves to the latest snapshot at or before that timestamp, for the read's backing table. Resolution happens **query-api-side**, not on the engine: the handler turns the selector into a concrete `SnapshotId` (the timestamp form via `Catalog::snapshot_as_of`), then ships that resolved id to the engine on a dedicated `AsOfStatementQuery` Flight ticket — a parallel surface to the standard `CommandStatementQuery` interop path, which stays untouched for callers that never ask for time travel. A malformed selector, or both selectors supplied together, is a 400; a well-formed selector that resolves to nothing (a pre-history timestamp, or an id the table never had) is a 404.

The two routes validate `as_of_snapshot` differently — a deliberate asymmetry, not a bug. `/objects/{type}` checks the id against the mirror's **liveness range** (`begin <= id AND (end IS NULL OR end > id)`), which is open-ended upward: an id above the table's current snapshot reads as *live* rather than 404ing. `/datasets/{schema}/{table}` instead looks the id up in exact **snapshot history**, so any id the table never had 404s. Unifying the object-read path onto history-backed validation is tracked as `#fut-timetravel-snapshot-id-validation`.

**Retention caveat:** this slice does not check the requested snapshot against the GC retention horizon. A selector that resolves to a snapshot whose data files have already been reclaimed by GC under-reads (a partial or empty result) rather than erroring; a horizon check that turns this into a clear error is tracked as `#fut-timetravel-retention-guard`. Time-travel reads also inherit the existing as-of-schema gap: the served Arrow schema is always the table's *current* schema, not the schema as of the selected snapshot (`#fut-iceberg-time-travel-schema`).

## Actions: governed insert, update, delete

`POST /actions/{name}` invokes a named ontology `ActionDef` against its target type — the governed write-back path, and the first live `Action::Write` enforcement. The JSON body parses against the action's declared parameters per logical type (`Long` as a string, `Date`/`Timestamp` as ISO strings — the exact inverse of the read renderer); required params must be present and non-null, unknown keys are rejected, and an action definition that no longer conforms to its target type is a distinct `Misconfigured` server-side fault rather than an opaque 500. Governance is two-layer: the coarse `Write` ACL gate, then fine-grained enforcement on the **affected row** — a pure, fail-closed in-memory evaluation of the policy's row filters against the concrete row (three-valued SQL semantics: an UNKNOWN verdict denies, mirroring how an UNKNOWN `WHERE` row is excluded from a read), plus column-level denial. Per-value model constraints (range/length/pattern/one-of declared on `PropertyDef`) run on the same resolved row and reject with a 422 naming the failed rule (#265) — the same `core` validator ingest's land gate uses, so both write paths enforce identical rules. Writes commit atomically with their lineage event through the engine and return the action's `run_id`. A single-step action's success body is the bare affected object with a **kind-true** status (`201 Created` for Insert, `200 OK` for Update/Delete — the status keys on the primary step's kind; #397); a **multi-step** action — one that commits several typed writes atomically in one transaction (e.g. `createOrderWithLines`: an `Order` plus its `LineItem`s, cross-step foreign keys resolved through named `bind`s) — returns an ordered `{steps:[{bind,target,objects}]}` envelope carrying **every** step's affected row, each labelled by its declared `bind` (when it declared one) and `target` type, with array order disambiguating unbound same-target steps (#396). The `X-Loom-Run-Id` header carries the run id for both shapes. A single-step **Insert** action may declare `downstream: Vec<JobTemplate>` — on commit each template (`kind` from the worker job-kind allowlist, validated at define time; a JSON `payload` whose `@self.<prop>` leaves resolve against the written row) is enqueued as a `NewJob` **atomically with the write** (the job is visible to a worker iff the write commits — rollback ⇒ no job), the write-then-derive primitive (slice 4 phase 1; Update/Delete/multi-step downstream is phase 2, gated at define time until then).

Beyond insert, `ActionKind` covers `Update` and `Delete` (#208): update is an identity-targeted PATCH (locate by declared identity, apply the field delta, recommit), delete removes the object — originally via whole-table copy-on-write, made O(change) for identity-bearing types by the inline-shadow rework (#331): a mutation writes one inline delta row (version or tombstone) that the engine's merge-on-read resolves below the governed layer, with a per-identity CAS closing the read→commit race (identity-less types keep whole-table COW). Actions also carry declarative custom logic: a param can bind to a differently-named property and an `ActionDef` can carry constant assignments (#269), and a property can be set by a **computed assignment** (#322) — a closed, total, injection-free expression grammar (literals, param/`@property` refs, arithmetic, string concat, comparisons, `if/then/else`, and a whitelisted function set incl. `now()`), type-checked at define time and evaluated to a plain value *before* the unchanged ACL and constraint gates, so computation cannot weaken governance; runtime arithmetic faults (division by zero, bad cast) are a 422, not a 500.

## Vector search

`POST /search/{type}/{index_name}` serves governed kNN over a declared vector index (#227): the body carries the query vector, `k`, and optional `nprobe`/`ef_search` knobs; column, metric, kind, and dimension resolve server-side from the named index (a wrong query dimension is a 400, an unknown index a 404). The result is a ranked `{id, distance}` list — ids and distances only, so no column masking applies; clients hydrate via `/objects`. Governance is the coarse type-level `Read` gate plus a row-filter **post-filter**: the engine's top-k ids are re-checked against the subject's row filters through a governed id-projection read, so a caller never sees an id their policy hides (the result may return fewer than `k`). For an identity-bearing vector type this survivor post-filter runs **unconditionally** (not only when a row filter exists) and keeps one hit per surviving identity — so a COW inline-shadow UPDATE's stale cold-index duplicate collapses to a single hit and a DELETE's tombstoned cold hit is dropped, the re-query reading the engine's live merged view (precedence-winner, tombstone-hidden) as the source of truth for which identities are live (#400; interim query-time mitigation — durable cold-entry removal stays with slice-2 compaction, `fut-cow-inline-shadow`). Freshness is maintained by auto-rebuild on flush (#240): end-capping inline vector rows enqueues a deduped index rebuild so just-flushed vectors do not silently vanish from results.

## Error contract and governance behaviour

The status mapping is uniform across reads: 403 `Forbidden` for any Read/Write denial, issued *before* existence is revealed (and for an empty permitted projection, or a tree/association read whose identity is governed); 404 for a genuinely unknown type, link, or index; 400 for the caller's request faults — bad filters, malformed chains and non-cyclic paths, ambiguous inverse links, depth/pagination violations; and an opaque `"internal error"` 500 for backend faults, whose detail is logged server-side rather than leaked (#140). Since #284, an uncoercible filter value returns a structured 400 body — `{"error":"bad_filter_value","column":…,"expected":…,"value":…}` echoing the expected logical type and the caller's own rejected operand — while visibility denials stay a bare column name (a permission signal never echoes a value); and `POST /actions` returns **422** for well-formed bodies that fail semantic parameter validation (missing/mistyped params, aligning with the constraint-violation 422 on the same path), reserving 400 for malformed JSON. The 400 classification is reserved for *caller-supplied* values: an engine-derived fault in `/search`'s row-filter post-filter — a mirror-returned hit identity that fails to coerce to its declared logical type, or a served vector type with no declared identity — is server-data-integrity, not caller-forgeable, so it classifies at its source (`QueryError::Internal`) as an opaque **500** with a single server-side `tracing::error!`, never a caller 400 echoing engine data (#339). The load-bearing invariants, held everywhere: deny-by-default; governance compiled into the SQL itself (row filters ANDed at every position, projections applied at compile time), not post-filtered in the app except where a design demands it (vector search); caller input only ever narrows; and every caller value is a bound parameter.

## Known gaps

- `#fut-ontology-types-pagination` — `/ontology/types` returns one unbounded page; honour cursor+limit if ontologies grow.
- `#fut-object-read-nonidentity-sort` — pagination orders by ascending identity only; no descending or arbitrary-column sort.
- `#fut-traversal-keyset-pagination` — traversal/graph-tail reads are unordered; no stable order + cursor over them yet.
- `#fut-composite-identity` — `identity` is a single column; multi-column natural keys fall back to `DISTINCT` dedup.
- `#fut-mandatory-identity` — identity stays opt-in; the `identity: None` `DISTINCT` fallback lingers until it is required.
- `#fut-scalar-derived-props` — no own-column/expression derived properties; needs a whitelisted expression surface.
- `#fut-derived-on-traversal` — derived properties serve on `read_object` only, not traversal/chain output.
- `#fut-multi-hop-aggregates` — no aggregates over a link chain, no derived-on-derived.
- `#fut-derived-materialization` — derived properties are read-time subqueries; no materialization for hot paths.
- `#fut-derived-filter-sort` — derived properties are not filter or sort targets.
- `#fut-or-link-graph-endpoints` — `_or` groups work on the object read only, not link/graph endpoints.
- `#fut-or-set-operand-escaping` — a literal backslash escape inside an OR-member set operand double-unescapes to a clean 400.
- `#fut-or-nested-predicates` — one level of OR under a top-level AND; no nested boolean predicate trees.
- `#fut-inverse-in-union` — the `?links=` union axis takes forward self-links only; no `~` members.
- `#fut-inverse-in-tail` — the `*` recursive core and its relational tail are forward-only.
- `#fut-graph-single-hop-direction` — the legacy `/graph/{link}` route ignores `?direction=`; `~` in `?path=` is the sole graph inverse surface.
- `#fut-graph-filter-addressing` — no per-occurrence/positional filter addressing for repeated links (the `/links` 400 case).
- `#fut-weighted-edges` — reachability and trees are unweighted (fewest hops); no min-cost traversal.
- `#fut-tree-union-tail-routes` — `?tree=true` covers the self-link and path-cycle routes only; union and core+tail trees are 400.
- `#fut-tree-materialized-paths` — parent pointers only; no materialized full paths, k-shortest, or all-shortest enumeration.
- `#fut-set-depth-annotation` — the flat reachable-set response carries no per-node depth (the tree does).
- `#fut-governed-scan-pushdown` — the governed table provider pushes no client projection/filter/limit into the inner scan yet.
- `#fut-query-multitype-joins` — no multi-type queries/joins, schema sidecar, or timezone-aware timestamps.
- `#fut-timetravel-snapshot-id-validation` — `/objects` gates `as_of_snapshot` via the mirror's open-ended-upward liveness range, so an id above the current snapshot reads live instead of 404ing, unlike `/datasets`' exact snapshot-history lookup.
- `#fut-timetravel-retention-guard` — an as-of selector resolving to a GC'd (aged-past-horizon) snapshot under-reads rather than erroring; add a retention-window check.
