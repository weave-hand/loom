# Yew WASM UI Experiment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Teach loom's buck2 build to cross-compile Rust to `wasm32-unknown-unknown` and build a minimal Yew UI into a browser-loadable bundle (`buck2 build //src/ui:bundle → dist/{app_bg.wasm, app.js, index.html}`).

**Architecture:** Add a wasm `rust-std` dist + a `wasm32` constraint and `//platforms:wasm` platform; make `toolchains//:rust` `select()` its target triple and std dist on that constraint. The `src/ui` app pins `default_target_platform = //platforms:wasm` so the native `//src/...` CI sweep cross-compiles it. A `wasm-bindgen-cli` buck tool turns `app.wasm` into browser glue; a genrule assembles `dist/`.

**Tech Stack:** buck2 + vendored prelude, hermetic Rust nightly `2026-03-28`, reindeer (third-party imports), Yew (CSR), wasm-bindgen.

## Global Constraints

- **Rust nightly:** `RUST_NIGHTLY = "2026-03-28"` — the wasm `rust-std` dist MUST use this exact version (`toolchains/BUCK`).
- **wasm-bindgen lockstep:** the `wasm-bindgen` *crate* version and the `wasm-bindgen-cli` *tool* version MUST be byte-identical, or the generated glue panics at module load. A single buck constant `WASM_BINDGEN_VERSION` is the source of truth, used for the CLI `http_archive` version AND copied verbatim into `src/ui/Cargo.toml` as an `=` pin.
- **Placement:** the crate lives at `src/ui/`, inside `//src/...` — subject to the strict pedantic+restriction clippy gate and the native CI sweep. Survive the sweep via the `default_target_platform` pin; satisfy clippy via crate-level `#![expect(...)]`, never by weakening the global `CLIPPY_ALLOWS`.
- **Linker:** the live `:rust` toolchain leaves `use_bundled_linker = False` (no `-Clinker` override). The wasm toolchain branch keeps it `False` too — rustc self-links wasm via its internal `wasm-ld`. Do NOT enable `use_bundled_linker`.
- **Host arch:** x86_64 Linux only for the `wasm-bindgen-cli` tool (matches the `rustfmt`/`rust-analyzer` host-only precedent). aarch64 host is out of scope.
- **reindeer footgun:** after any `cargo generate-lockfile`/`reindeer update`, run the **full** `buck2 build //src/...` + `buck2 test //src/...` and diff `Cargo.lock` against the merge-base for native/`links` crates before committing (per CLAUDE.md).
- **Tests:** integration-only; no inline `#[test]`. The build assertion (`buck2 build //src/ui:bundle` succeeding) is the test for this experiment. No `rust_test` target in `src/ui`.

- [ ] **Step 2: Add the wasm-bindgen-cli tool**

In `tools/BUCK`, following the `prek` block's tar.gz pattern (strip the wrapper dir, `cp` the binary), add:

```python
# wasm-bindgen-cli (https://github.com/rustwasm/wasm-bindgen) — generates the JS
# glue + a trimmed wasm for //src/ui. Its version MUST equal the wasm-bindgen
# *crate* version (src/ui/Cargo.toml pins `=WASM_BINDGEN_VERSION`), or the glue
# panics at load. x86_64 host only (matches rustfmt). Ships as a tar.gz whose
# single dir holds `wasm-bindgen`, so the genrule untars with --strip-components=1.
WASM_BINDGEN_VERSION = "0.2.100"

_WASM_BINDGEN_URL = "https://github.com/rustwasm/wasm-bindgen/releases/download/{v}/wasm-bindgen-{v}-x86_64-unknown-linux-musl.tar.gz"

http_archive(
    name = "wasm-bindgen-cli.tar.gz",
    urls = [_WASM_BINDGEN_URL.format(v = WASM_BINDGEN_VERSION)],
    sha256 = "REPLACE_ME",  # see Step 3
    type = "tar.gz",
    sub_targets = ["wasm-bindgen-{}-x86_64-unknown-linux-musl/wasm-bindgen".format(WASM_BINDGEN_VERSION)],
)

genrule(
    name = "wasm-bindgen-bin",
    out = "wasm-bindgen",
    cmd = "mkdir -p $TMP/x && tar -xzf $(location :wasm-bindgen-cli.tar.gz.tar.gz) -C $TMP/x --strip-components=1 && cp $TMP/x/wasm-bindgen $OUT && chmod +x $OUT",
)

command_alias(
    name = "wasm-bindgen",
    exe = ":wasm-bindgen-bin",
    visibility = ["PUBLIC"],
)
```

Note: `http_archive` for a `.tar.gz` with `type` set produces an extracted tree, but to mirror the repo's existing prek/btd pattern exactly (which download the archive then untar in a genrule), instead declare the download as a plain `http_file`-style archive. If your prelude's `http_archive` auto-extracts, drop the genrule and point `command_alias.exe` at the `sub_targets` entry. Verify against the prek block in `tools/BUCK` (lines ~198–212) and match whichever form it uses; the prek block is the canonical example.

```python
# Runs wasm-bindgen over app.wasm to emit ES-module glue (app.js + app_bg.wasm),
# then drops index.html alongside. Output dir is loadable in a browser when
# served over HTTP (the glue fetch()es the wasm, which file:// blocks).
genrule(
    name = "bundle",
    out = "dist",
    cmd = " && ".join([
        "mkdir -p $OUT",
        "$(exe //tools:wasm-bindgen) --target web --no-typescript --out-dir $OUT --out-name app $(location :app)",
        "cp $(location index.html) $OUT/index.html",
    ]),
    visibility = ["PUBLIC"],
)

# Convenience: serve the built bundle over HTTP via the hermetic python so the
# wasm actually loads (file:// fetch is blocked). `buck2 run //src/ui:serve`.
command_alias(
    name = "serve",
    exe = "toolchains//:python",
    args = ["-m", "http.server", "--directory", "$(location :bundle)"],
    visibility = ["PUBLIC"],
)
```

(If `toolchains//:python` is not directly runnable as a `command_alias.exe`, fall back to a genrule wrapper script that `exec`s `$(exe toolchains//:python) -m http.server --directory <dist>`; confirm the python target name in `toolchains/BUCK`.)

## Self-Review notes (for the implementer)

- **Spec coverage:** Task 1 = spec components 1–2 (wasm std + toolchain/platform); Task 2 = component 3 + bundle/serve (component 5 packaging); Task 3 = components 4–5 (reindeer + yew app) and all five Risks (version lockstep via the single `WASM_BINDGEN_VERSION` constant + `=` pin + `--version` check; linker via "leave `use_bundled_linker` off"; fixups in 3.4; reindeer blast-radius in 3.9; clippy in 3.5/3.8).
- **Two known unknowns to confirm against the prelude, not guess:** (a) whether your prelude's `http_archive` auto-extracts a `.tar.gz` (Task 2 Step 2 — mirror the prek block exactly); (b) whether `toolchains//:python` is a valid `command_alias.exe` (Task 2 Step 6 — fall back to a wrapper genrule if not). Both have explicit fallbacks in-line.
- **Toolchain select() risk:** if buck2 errors that the rust toolchain is analyzed in a configuration where the `root//platforms/constraints:wasm32` select key cannot resolve, the cause is the toolchain being configured under a platform lacking the constraint setting's default. Fix by giving `constraint_setting(name = "rust_target")` an explicit default value pointing at a `native` constraint_value, and add that `native` value to the `DEFAULT` platforms — but try the simpler `DEFAULT`-keyed select first (Task 1 Step 4), which is how `tools/coverage` does it.
