# Action enqueue-downstream slice 4 — PHASE 2 supplement

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this task-by-task. This is a **supplement** to the full-slice plan `2026-07-08-action-enqueue-downstream.md` — read that plan's **Architecture**, **Global Constraints**, and **Tasks 7–9** for rationale; this file re-grounds the *remaining* phase-2 work against current (post-#406) code and adds the one step the full plan lacks (removing the phase-1 scope gate). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Extend the atomic action→downstream-enqueue primitive (which #406 wired end-to-end for **single-step Insert**) to **Update**, **Delete**, and **multi-step** actions, complete the **overwrite** commit path so downstream jobs merge with vector-rebuild jobs rather than clobbering them, and **remove the phase-1 scope gate** that rejected everything but single-step Insert.

**Architecture:** The wire already carries `jobs_json` on all four write RPCs (#406) and `EngineActionClient` already serialises + forwards `jobs` for all four. Phase 2 fills the three paths where the value is still dropped on the engine side (`write_steps`, `overwrite_table`, `write_delta` handlers → `IcebergActionWriter` → the postgres land/commit fns), resolves real jobs at the two query-api call sites still passing `&[]` (`run_mutate`, `run_multi_step`), and deletes `validate_downstream_scope`. Atomicity is inherited (the job rides the write's commit tx) exactly as in phase 1 — no new primitive.

**Tech Stack:** Rust, tonic/prost proto (auto-regenerated by `:pb-gen`), sqlx (no new SQL this phase — no `.sqlx` regen needed), DataFusion, axum; buck2 `rust_test`/`loom_fixture_test`.

## Global Constraints (in addition to the full-slice plan's)

- **No `.sqlx` regen, no migration.** Phase 2 adds no SQL. (The full plan's Task 2 / migration `0039` already landed.)
- **Merge, never clobber, on the overwrite path.** `overwrite_parquet_snapshot` already sets `CommitExtras.jobs = &rebuild_jobs` (vector-index rebuild jobs). The action's downstream jobs must be **concatenated** with `rebuild_jobs` into one `Vec<NewJob>`; `pg_insert_if_absent`'s `(kind,payload)` dedup handles collisions. Do NOT overwrite `rebuild_jobs`.
- **Atomicity inherited.** Every resolved `NewJob` rides the write's existing commit `tx` via `pg_insert_if_absent` (or `CommitExtras.jobs`). No new tx. Rollback ⇒ no job — pinned by the Task 4 e2e.
- **Proto is unchanged** this phase (all four `jobs_json` fields already exist) — no `:pb-gen` regen needed, though a rebuild is harmless.
- **`@self` context per kind:** the affected row's `pairs: Vec<(String, SqlValue)>` (identity included) is the `@self.<prop>` context. For multi-step, `@self` = the **primary (first) step's** resolved row (cross-step `@bind.prop` payload refs stay out of scope — [[fut-action-cross-step-expr-refs]]).
- **`ActionEngine` trait ripple.** The trait already declares `jobs` on all four methods; the two default-erring impls (`write_delta` `serving.rs:399-413`, `write_steps` `:422-429`) bind it as `_jobs` — leave them (they still error). `IcebergActionWriter`'s methods are **inherent** (engine-side), NOT the trait — their signatures are edited independently below.
- **Tests are `rust_test`/`loom_fixture_test` integration targets.** Strict clippy on production code; tests exempt via `loom_rust_test`/`loom_fixture_test`. Conventional Commits + the two commit trailers.
