# Custom-logic actions slice 4 — enqueue-downstream (write-then-derive) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On commit, a governed action **atomically enqueues a downstream job** in the *same* unit of work as its write — `ActionDef` gains `downstream: Vec<JobTemplate>`, the write path resolves each template to a `NewJob` (payload `@self.<prop>` leaves filled from the written row), and threads them through the write seam so the job lands in the engine's commit transaction. A worker sees the job **iff** the write committed (rollback ⇒ no job, no row, no lineage).

**Architecture:** The atomic-enqueue primitive already exists at the commit layer — `CommitExtras.jobs: &[NewJob]` (`commit_mirror.rs:40`), applied by `apply_commit_extras` (`commit_mirror.rs:89` → `pg_insert_if_absent`) inside the snapshot-commit `pool.begin()` tx. The gap is the **action level**: no `ActionDef` can *declare* a job, and the action write seam leaves `CommitExtras.jobs` at the `&[]` default. This slice (a) adds the `downstream` declaration + define-time validation, and (b) threads the resolved `NewJob`s from `query-api` → `ActionEngine` trait → `EngineActionClient` → `GrpcQueueClient` → **gRPC proto** (`jobs_json`, matching the existing `columns_json`/`lineage_json` wire convention) → engine `IcebergActionWriter` → `land`/`write_steps`/`overwrite_parquet_snapshot`/`write_inline_delta` → `CommitExtras.jobs`. Atomicity is **inherited** (the job rides the write's commit tx); this slice adds declaration + threading only.

**Tech Stack:** Rust, sqlx (compile-time `query!`, committed `.sqlx` cache), tonic/prost proto (auto-regenerated by the `:pb-gen` genrule), axum, DataFusion; buck2 `rust_test`/`loom_fixture_test`.

## Spec corrections (investigated, current code — the spec's line numbers are stale)

- The spec says the enqueue point is `append_parquet_snapshot(jobs)` (`iceberg_landing.rs:149`) and `Tx::enqueue` (`transaction.rs:41`). **Wrong on both counts.** The real enqueue is `CommitExtras.jobs` (`commit_mirror.rs:40`) → `apply_commit_extras` loop (`commit_mirror.rs:89`) → `pg_insert_if_absent` (`queue.rs:37`). `Tx::enqueue` (`transaction.rs:58`) is a *single*-`NewJob` seam on the higher-level `ControlPlane::begin()` tx, **not** used by the landing path. This plan threads to `CommitExtras.jobs`.
- The spec calls this "smallest of the three slices; plumbing largely landed." **Understated.** The action write seam crosses gRPC: `ActionEngine` trait → `EngineActionClient` → `GrpcQueueClient` → proto → engine `IcebergActionWriter`. `GrpcQueueClient` does not enqueue today. So the threading is real work across 5 crates (query-api, engine-wire proto, engine, engine-serving, postgres-iceberg), for **all four** write RPCs (`WriteObject`/`WriteSteps`/`OverwriteTable`/`WriteDelta` — confirmed all cross the wire). The shared infra (one `jobs_json` field + one serialize/deserialize + one `CommitExtras` merge) makes the 4-path cost ~1.5× a 1-path cost, so all kinds land together.
- `ActionDef` uses a `#[serde(from = "ActionDefRepr", into = "ActionDefRepr")]` bridge (an `untagged` `Flat`|`Stepped` enum) — a new action-level field must be added to **both** variants (with `#[serde(default)]` on `Flat` for legacy back-compat) and threaded through both `From` impls. `ActionDef` is **not** a JSON blob: it is normalized across 4 SQL tables, so `downstream` needs a real migration + table + `query!` + `.sqlx` regen.

## Scoping decisions (deliberate; spec-aligned)

- **Payload refs = `@self.<prop>` only** (the written row's properties, including the identity). The spec's headline use case — `{ orderId: @self.id }` — is fully delivered. Arbitrary *param* refs require plumbing the resolved param env through `resolve_action_row` (a ripple) and are **deferred**; this matches the spec's allowed "(no arithmetic) plain `@self.<identity/prop>` substitution" scoping. Both `@self.<prop>` and bare `@<prop>` notation are accepted (the leaf-walker strips an optional `self.` prefix).
- **Define-time validation in both adapters** via a shared `core` helper (`kind` ∈ allowlist; every `@<prop>` payload leaf names a real property of the primary target — identity refs are naturally enforced since the identity property exists iff declared). This honors the spec's "define-time rejection" + testkit; it needs only `core` types (`ObjectType`, `ParamDef`, `NewJob`), **not** the query-api `expr` module.
- **Multi-step `@<bind>.<prop>` payload refs are out of scope** (deferred — spec's "single-object actions only `@self` is available" fallback). Multi-step actions *can* still declare `downstream`; their payload refs resolve against the **primary** (first) step's target row.
- **No conditional enqueue** (a declared job always enqueues on commit). **No new job kinds/handlers** (enqueues existing kinds only).

## Global Constraints

- **Atomicity is inherited, not built.** Resolved `NewJob`s ride the write's commit tx via `CommitExtras.jobs`. Rollback ⇒ no job. Tests (Task 9) pin commit-or-neither.
- **`jobs_json` wire convention.** Add a `string jobs_json = <N>;` field to `WriteObjectRequest`/`WriteStepsRequest`/`OverwriteTableRequest`/`WriteDeltaRequest` (empty string ⇒ no jobs). Engine side deserializes `Vec<NewJob>` and passes `&[..]` as `CommitExtras.jobs`. This mirrors the existing `columns_json`/`lineage_json` string fields on these requests.
- **Proto auto-regenerates** via the `:pb-gen` genrule (`engine-wire/BUCK`): editing `proto/engine_control.proto` regenerates `pb` on `buck2 build`. No manual protoc.
- **`.sqlx` cache must be regenerated** after the new `query!` in Task 2: run `tools/sqlx-prepare.sh` and commit the new `query-*.json` under `src/control-plane/postgres/.sqlx/`. The `:sqlx-cache-check` test gates freshness.
- **ActionEngine trait ripple.** Adding `jobs: &[control_plane_core::NewJob]` to `write_object`/`overwrite_table`/`write_steps`/`write_delta` ripples to **every** impl. `grep -rn 'fn write_object\|fn overwrite_table\|fn write_steps\|fn write_delta' src` and fix each (production `EngineActionClient` + every in-process test stub). The trait's default-erring impls for `write_delta`/`write_steps` (`serving.rs:397/419`) keep their `&[]` default-arg-free shape by taking `jobs` and ignoring it. Do NOT trust a hardcoded list — grep.
- **Migration number is `0039`** (latest is `0038_consolidate_trigger.sql`). The migrations glob + `.sqlx` filegroup in `postgres/BUCK` auto-include new files — no BUCK edit.
- **All four write paths symmetric.** `write_object`→`land`, `write_steps`→`iceberg_landing::write_steps`, `overwrite_table`→`overwrite_parquet_snapshot`, `write_delta`→`iceberg_inline::write_inline_delta`. Each gains `jobs: &[NewJob]` merged into its `CommitExtras` (or, for `write_inline_delta`, its existing commit path).
- **Tests are `rust_test`/`loom_fixture_test` integration targets.** Clippy strict on production code (panic-safety lints enforced; tests exempt via `loom_rust_test`). Conventional Commits + commit trailers.
- **Insert + Update + Delete + multi-step all carry downstream.** The primary step's resolved row (its `pairs: Vec<(String, SqlValue)>`, incl. identity) is the `@self` context for every kind.

```rust
//! Define-time validation for action `downstream` job templates.

use crate::{ControlPlaneError, JobTemplate, ObjectType, ParamDef, KNOWN_JOB_KINDS};

/// Collect every `@<name>` / `@self.<name>` reference leaf in a JSON payload.
fn ref_names(payload: &serde_json::Value) -> Vec<String> {
    let mut out = Vec::new();
    match payload {
        serde_json::Value::String(s) if s.starts_with('@') => {
            let name = s.trim_start_matches('@').trim_start_matches("self.");
            out.push(name.to_string());
        }
        serde_json::Value::Object(map) => for v in map.values() { out.extend(ref_names(v)); },
        serde_json::Value::Array(arr) => for v in arr { out.extend(ref_names(v); },
        _ => {}
    }
    out
}

/// Validate every downstream template of an action against its primary target:
/// `kind` is a known worker kind; every payload `@self.<prop>` leaf names a real
/// property (the identity property exists iff the target declares one, so an
/// `@self.id` on an identity-less target fails here). Pure/static — no expr eval.
pub fn validate_action_downstream(
    downstream: &[JobTemplate],
    primary_target: &ObjectType,
) -> Result<(), ControlPlaneError> {
    let prop_names: std::collections::HashSet<&str> =
        primary_target.properties.iter().map(|p| p.name.as_str()).collect();
    for jt in downstream {
        if !KNOWN_JOB_KINDS.contains(&jt.kind.as_str()) {
            return Err(ControlPlaneError::Validation(format!(
                "downstream job kind `{}` is not a known worker kind", jt.kind
            )));
        }
        for name in ref_names(&jt.payload) {
            // `@self.<prop>` only this slice (params deferred). Any non-property leaf is
            // rejected — including `@self.id` when the target has no identity (the id
            // property exists iff identity is declared).
            if !prop_names.contains(name.as_str()) {
                return Err(ControlPlaneError::Validation(format!(
                    "downstream payload references unknown `@self.{name}` (not a property of `{}`)",
                    primary_target.name.0
                )));
            }
        }
    }
    Ok(())
}
```

```rust
//! Resolve action `downstream` templates to concrete [`NewJob`]s at invoke time.

use control_plane_core::{JobTemplate, NewJob};
use crate::serving::SqlValue;

/// Coerce one resolved cell to its JSON form. Mirrors `crate::render::natural`
/// (`render.rs`, the read renderer's `SqlValue→json` coercion — make it `pub(crate)`
/// and delegate, or duplicate this 7-arm match). `SqlValue` is `Text/Int/Bool/Double/
/// Date/Timestamp/Null` (`serving.rs:22`).
fn to_json(v: &SqlValue) -> serde_json::Value {
    match v {
        SqlValue::Null => serde_json::Value::Null,
        SqlValue::Int(i) => serde_json::json!(i),
        SqlValue::Double(f) => serde_json::json!(f),
        SqlValue::Bool(b) => serde_json::json!(b),
        SqlValue::Text(s) => serde_json::json!(s),
        SqlValue::Date(d) => serde_json::json!(crate::serving::iso_date(d)),
        SqlValue::Timestamp(t) => serde_json::json!(crate::serving::iso_timestamp(t)),
    }
}

fn resolve_value(v: &serde_json::Value, self_row: &[(String, SqlValue)]) -> serde_json::Value {
    match v {
        serde_json::Value::String(s) if s.starts_with('@') => {
            let name = s.trim_start_matches('@').trim_start_matches("self.");
            match self_row.iter().find(|(c, _)| c == name) {
                Some((_, val)) => to_json(val),
                None => v.clone(), // unresolved ref left as-is (define-time validation should prevent this)
            }
        }
        serde_json::Value::Object(m) => serde_json::Value::Object(
            m.iter().map(|(k, vv)| (k.clone(), resolve_value(vv, self_row))).collect()
        ),
        serde_json::Value::Array(a) => serde_json::Value::Array(
            a.iter().map(|vv| resolve_value(vv, self_row)).collect()
        ),
        other => other.clone(),
    }
}

pub fn resolve_downstream(templates: &[JobTemplate], self_row: &[(String, SqlValue)]) -> Vec<NewJob> {
    templates
        .iter()
        .map(|t| NewJob {
            kind: t.kind.clone(),
            payload: resolve_value(&t.payload, self_row),
            run_at: None,
            priority: 0,
        })
        .collect()
}
```
